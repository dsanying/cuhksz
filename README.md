# 港中深资源站

面向香港中文大学（深圳）学生的校园、学业与资源导航站。项目使用 Hexo 与 Butterfly 主题，部署到 GitHub Pages。

## 本地开发

```bash
npm ci
npm run dev
```

课程资料文件托管于阿里云盘；本站只维护课程代码与公开分享链接，不提交资料文件本体。

```bash
npm run build
```

### 课程资料维护与分享

阿里云盘根目录使用 `港中深课程资料库`，其下**每门课程一个一级文件夹**。本站按课程代码搜索，点击课程卡片后打开该课程的独立公开分享链接；不再扫描第三方网盘，也不使用 GitHub Action、定时任务或仓库 Secret。

已核对的阿里云盘现有顶层目录使用大写课程代码（如 `CSC3001`、`DDA3020`）。本地资料库与阿里云盘统一使用下列层级：`课程代码/学习资料|考试资料|作业习题|其他资料/文件`。上传时以本地已整理目录为准；历史网盘中的英文中间目录不再作为新资料的命名依据。

新增或更新资料时：

1. 在阿里云盘对应课程文件夹中整理文件；没有课程则新建以课程代码命名的文件夹。
2. 为该课程文件夹创建“永久有效、公开链接”的分享。
3. 将链接填入 `source/course-resources/aliyun-manifest.json` 中相同 `code` 的 `url` 字段，并更新 `updatedAt`。
4. 运行 `npm run build`；确认无误后按正常流程提交、推送和部署。

阿里云盘可能限制每日新建分享数量。达到额度时，不要删除或改动已有课程资料；待额度恢复后继续补齐 `url` 即可。没有 `url` 的课程会在页面显示“分享链接待补齐”，不会误导访问者进入错误目录。

## 课程资料维护规范

GitHub 仓库只保留课程目录、站点源码和公开说明；课程资料文件存储在阿里云盘。资料文件不通过 GitHub raw、jsDelivr 或 GitHub Release 分发。

### 公开收集与提交

欢迎通过 Pull Request 补充或修正课程链接、命名、分类和说明。资料文件本体请先通过 Issue 说明课程编号、资料类型和资料来源，再由维护者整理并上传至阿里云盘。

不熟悉 Git 时，也可直接通过邮件 `dsanying@qq.com` 或 Issue 提交资料线索、失效链接和删除请求。

### 文件夹分类

顶层目录优先使用课程编号，例如 `AAA0000`、`BBB0000A`；跨课程共享资料可以使用组合目录，例如 `AAA0001&0002`；非课程资料放入 `其他资料`。

每个课程目录下按资料用途分类：

- `学习资料`：教材、参考书、课件、笔记、课程大纲、Review 与复习资料等。
- `考试资料`：期中、期末、Quiz、样题、真题及其考试答案、允许考试携带的 cheating paper 等；一般 Review/复习资料不放在此类。
- `作业习题`：作业、习题、题解、题库。
- `其他资料`：校园通用资料等不属于以上类型的文件。

### 何时使用额外文件夹

课程目录默认只保留上述四个分类目录，**不要**按下载来源、GitHub 仓库名、学生姓名、`Course Documents`、`内容` 或压缩包名称额外嵌套。

仅在以下两种情况使用分类目录下的额外文件夹：

1. 同一套资料的相对路径是运行、编译或阅读所必需的，例如教师提供的 starter code、实验模板或官方数据包；使用简洁中文主题名，如 `作业习题/作业二_模板/`。
2. 同一课程不同学期、不同版本的资料会发生同名冲突或明显混淆；使用 `YYYY_季节`，例如 `学习资料/2025_秋季/`。

额外目录最多两层，目录名使用 `_` 分隔且不超过 60 个字符。普通 PDF、课件、题目、样卷和参考资料应直接放在所属分类目录中。只有一个普通文件的目录没有存在价值，必须展平；`课程资料`、`课程笔记`、`样卷汇总`、`期中样卷`、`期末样卷`这类泛化中间目录也必须展平。

额外目录仅可用于以下两类例外：一是相对路径不可拆分的教师模板、starter code、数据包或源码课件；二是同一分类下文件超过 12 个且可按明确主题或学期分组。目录名必须直接说明内容，例如 `ECO3121_教程课件源码`、`2025_秋季`；不得出现“资料”“文件”“内容”“新建文件夹”“下载”等空泛名称。

### 作业与项目资料的收录边界

课程资料库只收录可供后续同学学习、由课程或教师公开发布的材料；不保存学生的个人作品、提交物或身份信息。

**可以保留：**

- 教师发布的 Assignment、Homework、Lab、Project 题目、任务书、评分细则、模板、starter code、公开测试、课程数据和实验环境说明。
- 教师明确公开的参考答案、示例实现或样例报告；文件名应标注 `Official`、`Sample` 或 `WithSolution`，避免与学生作品混淆。

**不得放入，发现后移至待复核并从上传清单排除：**

- 学生个人项目源码、报告、演示、提交压缩包、可执行文件、训练输出、个人笔记仓库和作业答案实现。
- 含学生姓名、学号、联系方式、成绩、考勤、分组、座位、提交记录等个人信息的文件。
- Git 历史和开发环境产物，例如 `.git/`、`.DS_Store`、`__MACOSX/`、`__pycache__/`、`node_modules/`、`dist/`、`build/`、`.o`、`.obj`、`.pyc`、`.class`、日志和 IDE 临时文件。

名称中仅出现 `Project`、`Homework` 或课程代码并不足以证明可以收录。无法确认是否为教师发布材料时，移入 `_待复核/待确认来源/`，不要直接上传或删除。

### 文件命名

- 课程目录名只使用标准课程代码的大写形式，例如 `CSC3001`、`FIN1010S`；不要使用教师姓名、学生昵称、GitHub 用户名、学期群名或课程中文全称作为一级目录。
- 分类目录固定使用中文：`学习资料`、`考试资料`、`作业习题`、`其他资料`。额外目录使用简洁中文主题名，例如 `作业习题/作业二_模板/`、`学习资料/2025_秋季/`；不使用下载来源和个人名称。
- 普通文件优先采用 `课程代码_年份_资料标题.扩展名`，资料标题使用简洁中文，例如 `CSC3001_2025_课程大纲.pdf`、`STA2002_2024_期中样卷.pdf`、`DDA3020_2025_作业二_题目.pdf`。
- 英文缩写、课程术语和原始书名可保留，例如 `CSC3100_2024_Lecture_01_指针.pdf`、`ENG1001_2025_The_Great_Gatsby_阅读材料.pdf`。不得为了中文化而改写正式英文书名、论文题目、软件包名或教师指定标题。
- 日期与学期统一为 `YYYY`、`YYYYMMDD`、`YYYY_春季`、`YYYY_夏季`、`YYYY_秋季`；不用 `24fall`、`2024F`、`2024秋`、`final版` 等混杂写法。
- 资料类型中文命名统一使用：`课程大纲`、`课件`、`阅读材料`、`复习资料`、`样卷`、`期中`、`期末`、`测验`、`作业`、`实验`、`项目`、`题目`、`模板`、`官方答案`。例如 `MAT3007_2024_期末_样卷_官方答案.pdf`。
- 文件名以课程代码开头，例如 `AAA0000_2023_期中_样卷.pdf`。组合课程可保留具体子课程代码，例如 `AAA0002_2024_期中_样卷.pdf`。
- 文件名使用 `_` 分隔；避免空格、连续下划线、下载尾缀 `(...)`、`副本`、`copy`，以及 Blackboard 来源目录名如 `Course Documents`、`内容`。
- 文件名一律使用半角 ASCII 下划线 `_` 作为分隔符；全角空格、中文冒号、英文冒号、逗号、分号和斜杠均改为 `_`。正式书名、术语中的连字符可保留；不要混用空格、`-`、`_` 作为字段分隔。
- 操作系统产生的同名副本尾缀 `(1)`、`（1）`、`(2)`、`（2）` 不得保留：内容不同的第二版起改为 `_v2`、`_v3`；内容完全相同则按 SHA-256 只保留命名更规范的一份。括号中属于标题正文的内容应改写为清晰文字，例如 `Lecture_02_续`，不要让括号承担版本含义。
- `副本`、`copy`、`final`、`最新版`、`新`、`新建文件夹`、`下载`等不表达资料性质的尾缀不得使用。确有版本差异时写明版本或学期，例如 `_v2`、`_2025_秋季`、`_修订版`。
- 压缩包先检查内容：可正常展开且不依赖压缩包本身的，解压后按分类整理；仅在保持教师模板、代码或数据的相对路径时保留一个中文主题目录。解压成功后的原压缩包移入待复核区，不与整理后的资料同时上传。
- 仅包含在线笔记链接的 `.txt` 不是课程资料正文。先检查链接类型；不能在未登录状态下合规导出为本地文件的，改为 `课程代码_主题_在线笔记.html`，页面内放置可点击的原始链接。原 `.txt` 移入待复核区，不上传为资料文件。
- 同一文件夹内需要排序的内容使用补零数字，例如 `课件_01`、`第02周`、`习题课_03`、`作业_04`、`作业_05`。
- 考试资料使用 `课程代码_年份[_夏季][_样卷]_期中|期末[_官方答案].pdf`；无法确定年份时保留清晰标题，例如 `AAA0000_期中_样卷_官方答案.pdf`。
- 同名但内容不同的文件使用 `_v2`、`_v3` 区分；不使用裸数字尾缀如 `_2` 或 `(2)`。
- 文件名尽量只写标题、年份、版次、讲次等必要信息，不重复写资料类型。英文书名、论文名、教师给定标题可以保留原文。
- 单个文件名控制在 `100` 个字符以内；自动整理时标题部分最多保留 `80` 个字符，为课程代码、版本号、扩展名和分片编号预留空间。
- 同一份资料只保留一份；若内容相同，优先保留更清晰、更干净、文件类型正确的版本。
- 超过网盘单文件限制的资料拆分为 `原文件名.part001-of-003.zip`、`原文件名.part002-of-003.zip` 等分片；编号必须补零并保留总片数。恢复时按编号下载全部分片后合并为原文件。
- 如果原文件是可展开的压缩包，优先解压成文件夹后按资料分类上传，而不是继续上传大压缩包。

### 本地审计与整理

整理本地副本前，先运行只读审计；审计会检查全部文件路径、类型、大小、目录结构、隐私风险和 SHA-256 重复内容，但不会改动文件：

```bash
node tools/audit-course-library.mjs \
  --root "$HOME/Downloads/港中深课程资料库" \
  --report /tmp/course-library-audit.json \
  --hash-duplicates
```

确认需要隔离的高风险项目、隐私文件和系统产物后，再显式加 `--quarantine`。这一步将文件移入同级的 `港中深课程资料库_待复核_YYYYMMDD/`，**不会永久删除**。随后执行以下命令应用已人工确认的课程归类、中文命名和题目保留规则：

```bash
node tools/organize-course-library.mjs \
  --root "$HOME/Downloads/港中深课程资料库" \
  --apply
```

脚本默认是 dry-run；只有传入 `--apply` 才会移动文件。不要将待复核目录直接上传至阿里云盘；复核确认后再单独恢复或删除对应资料。

第二阶段的目录展平、文件名安全规范化和已确认压缩包解压使用：

```bash
node tools/normalize-course-library.mjs \
  --root "$HOME/Downloads/港中深课程资料库" \
  --apply
```

该工具只自动处理无歧义的泛化分类目录与已核对的压缩包；课程术语、正式书名和内容语义不会被机器翻译或猜测改名。

### 收录与去重

- 优先收录与课程学习直接相关且难以替代的资料，包括课件、教材与阅读、笔记、教师发布的模板或示例代码、作业题目、考试与复习资料、课程大纲。学生完成的题解、实现和报告不在此列。
- 不收录考勤与签到记录、座位表、学生名单、分组名单、提交封面、查重承诺等教学管理文件；发现个人信息时直接剔除。
- 课堂录屏及可从公开来源重新获取的大体积音视频通常不收录；考试听力、课程实验素材等完成课程所必需的媒体可以保留。
- 内容去重使用文件内容的 `SHA-256` 摘要，不只比较文件名。摘要相同的文件仅保留命名和格式更规范的一份。
- 同一资料同时提供 PDF 和可编辑演示文稿时，默认保留更便于跨平台阅读的 PDF；若两者内容或用途不同则分别保留，并使用 `_v2` 等明确区分。
- 无扩展名、类型不明且超过 `100M` 的原始数据或媒体默认不收录；确属课程必需内容时，应先确认格式和用途再整理上传。

## 内容命名规范

文章标题与导航不是随意文案，而是站内检索、归档与长期维护的索引。新增或修改内容时遵循以下规则：

1. 使用简洁的中文标题，以“内容对象 + 文档类型”为基本结构，例如“跨学院转专业指南”“课程资料与电子课本”。
2. 操作类内容使用“指南”，推荐类使用“推荐”，集合类使用“汇总”，待办类使用“清单”；课程代码类使用“课程代码 + 主题”，例如“CEC1010 修读指南”。
3. 并列概念使用“与”，不使用 `&`；只有确有替代关系时才使用 `/`。
4. 英文缩写统一大写，并与中文之间保留一个空格；标题直接说明对象与用途，避免“如何快速高效地上手”这类泛化表述，例如“IT 指南”“SIS 使用指南”“SALL Centre 使用指南”“自由选修 PF 课程推荐”。
5. 不改动既有 `slug`，标题调整不得造成既有链接失效。

每一个直接指向页面的导航项必须与目标页面标题完全一致。当前对应关系如下：

| 书院与住宿 | `/dorm/` | 书院与住宿 |
| 校园地图 | `/map/` | 校园地图 |
